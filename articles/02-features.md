# 2. tinydbg的主要调试功能与命令简介

## 2.1 一级调试命令

tinydbg 提供了丰富的一级调试命令，用于启动、连接、管理调试会话。主要命令如下：

- **attach**：附加到已存在的进程进行调试。
  - 示例：`attach <pid>`
  - 说明：将调试器附加到指定进程ID的进程。
- **connect**：连接到远程调试后端。
  - 示例：`connect <address>`
  - 说明：通过网络地址连接远程调试服务，支持跨主机调试。
- **core**：加载core dump文件进行调试。
  - 示例：`core <core-file> [executable]`
  - 说明：分析进程崩溃时生成的core文件，支持回溯和变量查看。
- **debug**：以调试模式启动新进程。
  - 示例：`debug <path-to-binary> [args...]`
  - 说明：启动并调试指定的可执行文件。
- **exec**：直接执行并调试目标程序。
  - 示例：`exec <path-to-app> [args...]`
  - 说明：与debug类似，常用于直接运行目标程序。
- **trace**：对目标进程进行系统调用/事件跟踪。
  - 示例：`trace <pid> [options]`
  - 说明：跟踪进程的系统调用、信号等事件，便于问题定位。
- **log**：记录调试过程中的日志信息。
  - 示例：`log [options]`
  - 说明：启用或配置调试日志，便于问题追踪和分析。
- **redirect**：重定向被调试进程的标准输入输出。
  - 示例：`redirect <stdin> <stdout> <stderr>`
  - 说明：将tracee的输入输出重定向到指定文件或设备。

## 2.2 调试会话中的常用命令

在调试会话中，tinydbg 支持多种调试操作，主要包括：

- **程序运行控制**：
  - `continue`：继续程序执行。
  - `step`/`next`：单步执行（进入/跳过函数）。
  - `halt`：暂停程序运行。
- **断点管理**：
  - `break`：设置断点。
  - `clear`：清除断点。
  - `list`：列出所有断点。
- **变量与内存查看**：
  - `print`/`p`：查看变量值。
  - `examine`/`x`：查看内存内容。
- **线程与协程管理**：
  - `threads`：列出所有线程。
  - `goroutines`：列出所有Goroutine（Go语言特性）。
  - `thread`/`goroutine`：切换当前线程/协程。
- **调用栈与帧操作**：
  - `stack`/`bt`：查看调用栈。
  - `frame`：切换当前帧。
- **其他命令**：
  - `help`：显示帮助信息。
  - `exit`/`quit`：退出调试器。

> 各命令均可通过 `help <command>` 获取详细用法说明。例如：`help break`。

这些命令覆盖了调试过程中最常用的操作，极大提升了开发者定位和解决问题的效率。
